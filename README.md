## Описание проекта

Проект представляет собой backend-систему интернет-магазина, разработанную в рамках курса по WEB-разработке на Python.

Изначально проект был реализован как Django + DRF приложение с каталогом товаров, корзиной и заказами. Далее система была постепенно расширена в рамках нескольких спринтов:

- добавлен сервисный слой и доменные исключения;
- вынесена бизнес-логика из HTTP-слоя;
- реализован отдельный Flask-сервис пользовательского контента;
- реализован отдельный FastAPI-сервис уведомлений;
- добавлена JWT-авторизация пользователей;
- настроено межсервисное взаимодействие;
- добавлена CORS-поддержка для frontend-интеграции;
- проект покрыт тестами.

Итоговая система состоит из трёх backend-сервисов:

```text
Frontend
   |
   | HTTP + JWT
   v
Django API
   | \
   |  \ service-to-service HTTP
   |   v
   | FastAPI Notification Service
   |
   | JWT validation / product validation
   v
Flask UGC Service
```

## Общая архитектура

Проект построен как набор связанных backend-сервисов.

### 1. Django API

Основной сервис системы.

Отвечает за:

- регистрацию пользователей;
- авторизацию пользователей;
- работу с товарами;
- работу с корзиной;
- оформление заказов;
- хранение основной предметной области;
- вызов FastAPI-сервиса уведомлений после создания заказа.

### 2. Flask UGC Service

Отдельный сервис пользовательского контента.

Отвечает за:

- создание отзывов;
- получение отзывов по товару;
- модерацию отзывов через статусы;
- проверку существования товара через Django API;
- проверку JWT пользователя через Django Auth API.

### 3. FastAPI Notification Service

Отдельный сервис уведомлений.

Отвечает за:

- приём события о создании заказа;
- запуск фоновой задачи уведомления;
- логирование событий;
- демонстрацию JWT-защищённого endpoint;
- защиту внутреннего endpoint через service-to-service token.

### Цель

Показать использование Flask как отдельного backend-сервиса для пользовательских сценариев.

### Реализовано

- отдельный Flask-сервис;
- создание отзывов;
- получение отзывов;
- статусы отзывов;

- проверка пользователя через Django JWT;
- валидация входных данных;
- единый формат ошибок;
- тесты UGC-сервиса.

### Статусы отзывов

```text
pending
active
hidden
```

### Важная архитектурная особенность

Пользователь больше не передаёт `user_name` вручную.

При создании отзыва frontend отправляет JWT:

```http
Authorization: Bearer <access_token>
```

Flask UGC Service отправляет запрос в Django:

```http
GET /api/auth/me/
```

И получает текущего пользователя.

Это позволяет не дублировать пользователей в Flask-сервисе.

- тесты FastAPI-сервиса.

### Основной сценарий

После создания заказа Django вызывает FastAPI:

```http

```

FastAPI принимает событие и ставит фоновую задачу:

```text
Order-created notification requested
Background notification task scheduled
Sending order notification
Order notification sent
```

## Django-приложение `shop`

### Назначение

`shop` — основное доменное приложение интернет-магазина.

Оно отвечает за:

- каталог товаров;
- категории;
- корзину пользователя;
- позиции корзины;
- оформление заказа;
- позиции заказа;
- интеграцию с сервисом уведомлений.

------------------------------------------------------------------------

## Модели данных

### Category

Категория товаров.

Поля:

- `name` — название категории;
- `slug` — уникальный slug категории.

Используется для фильтрации товаров по категории.

------------------------------------------------------------------------

### Product

Товар интернет-магазина.

Поля:

- `category` — категория товара;
- `name` — название товара;
- `slug` — уникальный slug;
- `description` — описание;
- `price` — цена;
- `stock` — остаток на складе;
- `is_active` — активен ли товар;
- `created_at` — дата создания.

В API отображаются только активные товары:

```python
Product.objects.filter(is_active=True)
```

------------------------------------------------------------------------

### Cart

Корзина пользователя.

Поля:

- `user` — пользователь Django;
- `created_at` — дата создания корзины.

Один пользователь может иметь только одну корзину.

Это обеспечено связью:

```python
OneToOneField(User)
```

------------------------------------------------------------------------

### CartItem

Позиция корзины.

Поля:

- `cart` — корзина;
- `product` — товар;
- `quantity` — количество.

Для пары `cart + product` установлено ограничение уникальности.

Это предотвращает появление двух одинаковых товаров в одной корзине.

При повторном добавлении товара количество увеличивается.

------------------------------------------------------------------------

### Order

Заказ пользователя.

Поля:

- `user` — пользователь;
- `created_at` — дата создания;
- `status` — статус заказа.

Статусы:

```text
new
paid
shipped
```

------------------------------------------------------------------------

### OrderItem

Позиция заказа.

Поля:

- `order` — заказ;
- `product` — товар;
- `quantity` — количество;
- `price` — цена товара на момент оформления заказа.

Цена фиксируется в `OrderItem`, чтобы будущие изменения цены товара не меняли историю заказов.

------------------------------------------------------------------------

## Auth API

### Регистрация

```http
POST /api/auth/register/
```

Пример запроса:

```json
{
  "username": "max",
  "email": "max@test.ru",
  "password": "strongpass123",
  "password_confirm": "strongpass123"
}
```

Пример ответа:

```json
{
  "message": "Пользователь зарегистрирован.",
  "user": {
    "id": 1,
    "username": "max",
    "email": "max@test.ru"
  }
}
```

------------------------------------------------------------------------

### Логин

```http
POST /api/auth/login/
```

Пример запроса:

```json
{
  "username": "max",
  "password": "strongpass123"
}
```

Пример ответа:

```json
{
  "refresh": "...",
  "access": "..."
}
```

Токен `access` используется frontend-ом для защищённых запросов.

------------------------------------------------------------------------

### Обновление access-токена

```http
POST /api/auth/refresh/
```

Пример запроса:

```json
{
  "refresh": "..."
}
```

Пример ответа:

```json
{
  "access": "..."
}
```

------------------------------------------------------------------------

### Получение текущего пользователя

```http
GET /api/auth/me/
```

Требуется заголовок:

```http
Authorization: Bearer <access_token>
```

Пример ответа:

```json
{
  "id": 1,
  "username": "max",
  "email": "max@test.ru"
}
```

Этот endpoint используется не только frontend-ом, но и Flask UGC Service для проверки пользователя.

## Shop API

Базовый адрес:

```text
http://127.0.0.1:8000/api/shop/
```

------------------------------------------------------------------------

### Получение списка товаров

```http
GET /api/shop/products/
```

Поддерживается пагинация.

Также поддерживаются параметры:

```http
GET /api/shop/products/?search=iphone
GET /api/shop/products/?category=phones
GET /api/shop/products/?category=phones&search=air
```

------------------------------------------------------------------------

### Получение одного товара

```http
GET /api/shop/products/<id>/
```

Возвращает только активный товар.

Если товар неактивен или не существует, возвращается `404`.

------------------------------------------------------------------------

### Получение корзины

```http
GET /api/shop/cart/
```

Требуется JWT:

```http
Authorization: Bearer <access_token>
```

Если корзины ещё нет, она создаётся автоматически.

------------------------------------------------------------------------

### Добавление товара в корзину

```http
POST /api/shop/cart/add/
```

Требуется JWT.

Пример запроса:

```json
{
  "product_id": 1,
  "quantity": 2
}
```

Если товар уже есть в корзине, количество увеличивается.

------------------------------------------------------------------------

### Изменение количества товара в корзине

```http
PATCH /api/shop/cart/items/<cart_item_id>/
```

Требуется JWT.

Пример запроса:

```json
{
  "quantity": 5
}
```

Количество должно быть натуральным числом.

------------------------------------------------------------------------

### Удаление товара из корзины

```http
DELETE /api/shop/cart/items/<cart_item_id>/
```

Требуется JWT.

Пользователь может удалить только позицию из своей корзины.

------------------------------------------------------------------------

### Создание заказа

```http
POST /api/shop/orders/create/
```

Требуется JWT.

При создании заказа:

1. Проверяется, что корзина не пуста.
2. Проверяется наличие товаров на складе.
3. Создаётся заказ.
4. Создаются позиции заказа.
5. Уменьшается остаток товаров.
6. Корзина очищается.
7. После успешного commit отправляется событие в FastAPI Notification Service.

------------------------------------------------------------------------

### Получение списка заказов

```http
GET /api/shop/orders/
```

Требуется JWT.

Пользователь видит только свои заказы.

------------------------------------------------------------------------

### Получение одного заказа

```http
GET /api/shop/orders/<id>/
```

Требуется JWT.

Если заказ принадлежит другому пользователю, возвращается `404`.

## Интеграция Django с Notification Service

Файл:

```text
apps/shop/integrations/notification_client.py
```

После создания заказа Django отправляет запрос в FastAPI Notification Service:

```http
POST http://127.0.0.1:8001/api/notifications/order-created/
```

Тело запроса:

```json
{
  "order_id": 1,
  "user_id": 1,
  "message": "Order 1 created."
}
```

Для защиты используется service-to-service токен:

```http
X-Service-Token: dev-service-token
```

Важно: ошибка notification service не ломает создание заказа.

Если сервис уведомлений недоступен, ошибка логируется, но заказ остаётся созданным.

## Flask UGC Service

Базовый адрес:

```text
http://127.0.0.1:5000
```

### Назначение

UGC Service отвечает за пользовательские отзывы к товарам.

Он вынесен в отдельный сервис, чтобы показать микросервисное взаимодействие и использование Flask.

------------------------------------------------------------------------

### Создание отзыва

```http
POST /api/ugc/reviews/
```

Требуется JWT пользователя:

```http
Authorization: Bearer <access_token>
```

Пример запроса:

```json
{
  "product_id": 1,
  "text": "Хороший товар, всё понравилось.",
  "rating": 5
}
```

Важно: `user_name` не передаётся.

UGC Service сам получает пользователя через Django:

```http
GET http://127.0.0.1:8000/api/auth/me/
```

После этого отзыв создаётся от имени пользователя из JWT.

------------------------------------------------------------------------

### Получение отзывов

```http
GET /api/ugc/reviews/?product_id=1
```

По умолчанию возвращаются только отзывы со статусом:

```text
active
```

------------------------------------------------------------------------

### Изменение статуса отзыва

```http
PATCH /api/ugc/reviews/<review_id>/status/
```

Пример запроса:

```json
{
  "status": "active"
}
```

Допустимые статусы:

```text
pending
active
hidden
```

------------------------------------------------------------------------

### Health check

```http
GET /api/ugc/health/
```

Пример ответа:

```json
{
  "status": "ok",
  "service": "ugc"
}
```

## Особенности реализации

### 1. Тонкие view

В Django HTTP-слой не содержит бизнес-логики.

Views только:

- валидируют запрос;
- вызывают сервис;
- возвращают ответ.

------------------------------------------------------------------------

### 2. Service layer

Бизнес-операции вынесены в отдельные функции.

Это позволяет тестировать бизнес-логику отдельно от HTTP.

------------------------------------------------------------------------

### 3. Единый формат ошибок

Для доменных ошибок магазина используется единая структура:

```json
{
  "error_code": "...",
  "message": "...",
  "details": {}
}
```

------------------------------------------------------------------------

### 4. Транзакционность заказа

Создание заказа выполняется внутри:

```python
transaction.atomic()
```

Уведомление отправляется через:

```python
transaction.on_commit(...)
```

Это значит, что notification service вызывается только после успешного сохранения заказа.

------------------------------------------------------------------------

### 5. Межсервисная авторизация

Для внутренних запросов Django → FastAPI используется заголовок:

```http
X-Service-Token: dev-service-token
```

Это отделяет пользовательскую авторизацию от внутренней сервисной авторизации.

------------------------------------------------------------------------

### 6. Централизованная пользовательская авторизация

Пользователи хранятся только в Django.

Flask UGC Service не хранит пользователей.

При создании отзыва он проверяет JWT через Django Auth API.

------------------------------------------------------------------------

### 7. Background task

FastAPI не выполняет отправку уведомления прямо в request-response потоке.

Он добавляет задачу в background task.

------------------------------------------------------------------------

### 8. CORS

CORS включён во всех сервисах, чтобы frontend мог обращаться к backend API из браузера.
